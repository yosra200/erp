# نظام ERP — Laravel 12 + Filament 4

نظام إدارة موارد مؤسسية قابل للتوسع، مبني باستخدام Laravel 12 وFilament 4، ويقدم لوحة تحكم عربية لإدارة المنتجات والمخزون والمبيعات والمشتريات والعملاء والموردين.

## المزايا الحالية

| الوحدة | ما توفره |
| --- | --- |
| لوحة التحكم | مؤشرات مبيعات اليوم، عدد المنتجات، قيمة المخزون، تنبيهات المخزون المنخفض، ورسم مبيعات آخر 7 أيام. |
| المنتجات | الاسم، SKU، باركود فريد، التصنيف، الوحدة، تكلفة الشراء، سعر البيع، وحد إعادة الطلب، وحالة المنتج. |
| الباركود | يتم توليد باركود داخلي فريد يبدأ بـ `200` تلقائيًا عند إنشاء المنتج إذا لم يتم إدخاله يدويًا. |
| المخازن | تعريف عدة مخازن مع كود وعنوان وحالة تشغيل. |
| حركات المخزون | حركات وارد ومنصرف وتسوية مع المنتج والمخزن والمستخدم والمرجع والتاريخ. |
| فواتير البيع | العميل، المخزن، الأصناف، الكمية، السعر، خصم الصنف، الخصم العام، الضريبة، المدفوع، والإجمالي. تحفظ الفاتورة وتخصم الكميات تلقائيًا بعد التحقق من الرصيد المتاح. |
| فواتير الشراء | المورد، المخزن، الأصناف، التكلفة، الخصومات والضرائب والمدفوع. تورّد الكميات تلقائيًا وتحدث تكلفة المنتج بآخر تكلفة شراء. |
| العملاء والموردون | بيانات الاتصال والرقم الضريبي والعنوان وحالة الحساب وحد الائتمان للعملاء. |
| التصنيفات والوحدات | تنظيم المنتجات وفق تصنيفات ووحدات قابلة لإعادة الاستخدام. |
| سلامة الرصيد | حذف الفاتورة يحذف حركة المخزون المرتبطة بها حتى لا يبقى الرصيد غير صحيح. |

## المتطلبات

يحتاج المشروع إلى PHP 8.2 أو أحدث، Composer، امتدادات PHP الخاصة بـ SQLite أو MySQL وGD، Node.js وnpm لتجميع الواجهات، ثم Laravel 12 وFilament 4 وmPDF كما هو موضح في `composer.json`.

## التشغيل المحلي

```bash
git clone <رابط-المستودع>
cd erp-laravel
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
npm install
npm run build
php artisan serve
```

بعد تشغيل الخادم افتح:

```text
http://127.0.0.1:8000/admin
```

بيانات الدخول التجريبية:

| الحقل | القيمة |
| --- | --- |
| البريد الإلكتروني | `admin@example.com` |
| كلمة المرور | `password` |

ينبغي تغيير بيانات الدخول التجريبية قبل استخدام النظام في بيئة فعلية، كما ينبغي ضبط `APP_ENV=production` و`APP_DEBUG=false` في بيئة الإنتاج.

## قاعدة البيانات

يستخدم المشروع SQLite افتراضيًا لتسهيل التشغيل الأولي، ويمكن تحويله إلى MySQL أو PostgreSQL عبر إعدادات `.env`. الجداول الأساسية هي `products`, `warehouses`, `stock_movements`, `invoices`, `invoice_items`, `purchase_invoices`, و`purchase_invoice_items`، إضافة إلى جداول العملاء والموردين والتصنيفات والوحدات.

الرصيد الحالي لأي منتج لا يخزن كرقم منفصل؛ بل يحسب من حركات المخزون. الحركة `in` تزيد الرصيد، والحركة `out` تخصمه، والتسوية `adjustment` تقبل قيمة موجبة أو سالبة.

## اختبارات المشروع

```bash
php artisan test
vendor/bin/pint --test
```

الاختبارات الحالية تغطي توليد الباركود، احتساب رصيد المخزون، سيناريو فاتورة البيع، وسيناريو فاتورة الشراء وتحديث تكلفة المنتج.

## ملاحظات تطوير مهمة

تم منع تعديل فواتير البيع والشراء من موارد القائمة بعد اعتمادها؛ لأن تعديل فاتورة معتمدة يحتاج إلى عكس حركات المخزون وإعادة تطبيقها داخل معاملة قاعدة بيانات. يمكن إضافة دورة اعتماد وإلغاء رسمية لاحقًا، مع تسجيل سجل تدقيق للمستخدم والتاريخ والسبب.

تمت إضافة طباعة الفاتورة وتنزيلها PDF للبيع والشراء باستخدام mPDF لدعم العربية وRTL، مع قالب عربي وأزرار مباشرة داخل جداول Filament. الخطوات المناسبة للنسخة التالية تشمل قارئ باركود داخل شاشة البيع، صلاحيات تفصيلية للأدوار، تقارير الأرباح والمبيعات حسب الفترة، إدارة المصروفات والخزينة، وإشعارات إعادة الطلب.

## رفع المشروع إلى GitHub

بعد إنشاء مستودع فارغ على GitHub، نفذ:

```bash
git init
git add .
git commit -m "Initial ERP system with Laravel 12 and Filament"
git branch -M main
git remote add origin https://github.com/<username>/<repository>.git
git push -u origin main
```

لا ترفع ملف `.env` أو أي مفاتيح سرية. ملف `.env.example` هو الملف المناسب للمشاركة مع إعدادات عامة فقط.
